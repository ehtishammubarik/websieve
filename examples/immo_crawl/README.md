# immo_crawl — the original Scrapy deployment

This is the containerized Scrapy stack `websieve` grew out of: a Swiss
real-estate crawl running Scrapy under Scrapyd, writing to Postgres, with
Filebeat shipping logs. It is kept as a working integration example of the kind
of crawl `websieve` is designed to consume.

**It is not part of the `websieve` package.** Nothing here is installed by
`pip install websieve`, none of it is imported by `websieve`, and none of these
dependencies are `websieve` dependencies — the core has zero runtime
dependencies. These files used to sit in the repository root, where they read
as configuration for the package itself; they live here now so that they do not.

## What is here

| File | Role |
|---|---|
| `immo_crawl/` | The Scrapy project: spiders, items, pipelines, settings |
| `scrapy.cfg` | Scrapy project config; also the `scrapyd-deploy` targets |
| `setup.py` | Generated by `scrapyd-deploy`; used to build the egg it uploads |
| `requirements.txt` | Dependencies of **this example** (Scrapy, psycopg2, scrapyd) |
| `docker-compose.yml` | Brings up the crawler, Postgres and Filebeat together |
| `Dockerfile` | The crawler image |
| `Dockerfile.psql`, `psql_dump.sql` | Postgres image, seeded with the schema |
| `filebeat.yml` | Log shipping |
| `start.sh` | Container entrypoint: starts scrapyd, then deploys to it |
| `.env.example` | Database settings; copy to `.env` |
| `Jenkinsfile` | From the original CI. See the note at the bottom |

## Running it

Everything below is run from this directory, not the repository root.

```bash
cd examples/immo_crawl
cp .env.example .env      # then fill in CRAWL_DB_PASSWORD
docker compose up --build
```

Scrapyd comes up on `http://localhost:6800/`, and `start.sh` deploys the project
to it on boot.

To work on the spiders directly instead, without containers:

```bash
cd examples/immo_crawl
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
scrapy list                                     # the spiders in immo_crawl/spiders
```

`scrapy.cfg` points at `immo_crawl.settings`, so Scrapy commands must be run
from this directory for that to resolve.

## A note on the Jenkinsfile

`Jenkinsfile` runs `npm -v` in its Build and Test stages, via `bat` steps, in a
project with no JavaScript and no Windows agent. It looks like a scaffold that
was never filled in rather than a pipeline anything ran. It has been moved here
with the rest of the example rather than deleted, so that decision stays with
the maintainer.
